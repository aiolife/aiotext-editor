## 一、背景与结论

### 1.1 需求

> 提取 `fc1/fc2/u2b1/u2b2.dat` 中内容，改用其他格式，让任何一个通用编辑器打开，不要使用专属格式。

### 1.2 结论

| `TextPro65/data/fc1.dat` | `data-extracted/fc1.txt` | 1003 组 | ✓ 含 TextPro 文档示例"兔兎" |

`s2t.dat` / `t2s.dat`（简↔繁单字表）**未提取**：其内容与 OpenCC `STCharacters/STPhrases`、`TSCharacters/TSPhrases` 词库完全同质，按 v0.3 决策（OpenCC 为简繁主引擎）已被取代，不再打包。逆向记录见 §5，供未来需要时参考。

## 二、源文件二进制格式（逆向结果）

### 2.1 TEXTPRO 容器头部（u2b1/u2b2/s2t/t2s 及 `tables/*.tab` 共用）

| 偏移 | 长度 | 类型 | 含义 |
|------|------|------|------|
| 0x00 | 14 | UTF-16LE | 魔数 `"TEXTPRO"`（7 个码元） |
| 0x0E | 2 | u16 | 0（填充） |
| 0x10 | 4 | u32 | 版本（观测值：1 或 2） |
| 0x14 | 4 | u32 | **条目数**（u2b1=2122，u2b2=995，s2t=10002，t2s=6196） |
| 0x18 | 4 | u32 | 用途未知（u2b1/s2t/t2s=0x60，u2b2=0x04） |
| 0x1C | 4 | u32 | 0 |
| 0x20 | 4 | u32 | 描述字节长度 `descLen` |
| 0x24 | descLen | UTF-16LE | 表描述（如 `"uni2bg5预处理组合字表"`） |

### 2.2 u2b1.dat / u2b2.dat 记录格式（完全破解）

记录区自 `0x24 + descLen + 6`（对齐填充）开始，逐条排列：

```
record := u32 keyLen          // 恒为 2（键为单个 UTF-16 字符）
        | u32 keyCode         // 键字符的 UTF-16LE 码元（低 16 位有效）
        | u32 valLen          // 值字节长度（2 的倍数）
        | value[valLen]       // 值，UTF-16LE
        | u16 pad             // 0 填充
```

- **u2b1.dat**（`uni2bg5预处理异体字表`，63678 字节）：2122 条记录止于 0x84E6，值恒为单字符（BIG5 支持的异体字）。
- **u2b2.dat**（`uni2bg5预处理组合字表`，49598 字节）：995 条记录止于 0x64DC，值为组字式字符串（见 §3.4）。
- 记录区之后的剩余字节（约 29.6 KB / 23.7 KB）为**内部查询索引**（观测到 `(u16 字符, u32 偏移, u32 0)` 形式的记录），开放格式转换不需要，未解析。

### 2.3 fc1.dat / fc2.dat 格式（完全破解）

两文件**无** TEXTPRO 头部，采用简单防混淆处理：

```
密文 := 每字节 XOR 0x20
明文 := UTF-16LE + BOM，CRLF 分行；每行一个"异体字组"
```

- `fc1.dat`：8580 字节 → 1003 组。
- `fc2.dat`：127198 字节 → 10579 组。
- 旁证：XOR 0x20 后首两字节 `FF FE` 恰为 UTF-16LE BOM；密文中反复出现的 `2D 20 2A 20` 解码后恰为 `\r\n`（0x0D/0x0A）。

### 2.4 s2t.dat / t2s.dat（部分探明，未提取）

TEXTPRO 头部 + 哈希桶索引（`(u32 池偏移, u32 首字符, u16 填充)` 10 字节记录）+ UTF-16LE 字符串池（NUL 分隔，含词组如 `"６海里"`）+ trie 结构节点（`(u16 键长, u16 码元, u32 子偏移)`）。尾部字符串池已可直接读取，但完整 trie 遍历规则未还原。**产品不使用这两个文件**（OpenCC 取代）。

## 三、开放格式定义（产品数据文件规范）

以下 4 个文件在脚手架阶段迁入 `src-tauri/data/legacy/`，由 `core::data_tables` 以纯文本方式加载。

### 3.1 fc1.txt — 完全等同异体字组表

| 属性 | 值 |
|------|-----|
| 编码 | UTF-8 with BOM |
| 行尾 | CRLF |
| 行数 | 1003 |
| 行格式 | 每行一个组，组内字符直接连排，**无分隔符**；首字符为最常用形 |
| 注释 | `#` 开头的行在产品解析时忽略（当前文件无注释行） |

**语义**：用于文件比较（F-06）的"忽略异体字（**完全等同**）"档位——组内任意两个字符视为相同。

示例行：

```
兔兎
医醫毉
携㩗㩦攜擕
铁鐵銕
```

**解析要点**：组内含增补平面字符（如 `𩅯`），必须按 **Unicode 码点**迭代，不可按 UTF-16 码元切分。

**与 TextPro 语义的对照**：TextPro 帮助文档"'完全等同'指音义全同的异体字，例如'兔兎'"——`fc1.txt` 第 5 组即 `兔兎` ✓。注意少数组包含与简化字同形的古字（如 `铁`、`医`），这是历史异体字的真实数据，非简繁对照（fc1 中不含任何"万萬、后後、里裡"式简繁对，已验证 0 命中）。

### 3.2 fc2.txt — 部分等同异体字组表

| 属性 | 值 |
|------|-----|
| 编码 | UTF-8 with BOM |
| 行尾 | CRLF |
| 行数 | 10579 |
| 行格式 | 同 fc1.txt |

**语义**：文件比较"忽略异体字（**部分等同**）"档位（TextPro 文档示例"奔犇逩"即出自此表家族；fc2 中该组为 `奔倴𢍃𡗲𥤀𣦴渀犇䄯𧾜𧿣𨁼𨃦逩𩦥`，fc1 中另有精简组 `奔犇逩`）。

### 3.3 u2b1.tsv — BIG5 异体字回退表（已弃用，仅存档）

| 属性 | 值 |
|------|-----|
| 编码 | UTF-8 with BOM |
| 行尾 | CRLF |
| 行数 | 2122 |
| 行格式 | `键<TAB>值`——键为 BIG5 不支持的 Unicode 字符（1 字），值为 BIG5 支持的异体字 |

**语义（v0.5 起弃用）**：原为 F-02 保存为 BIG5 时的异体字回退；现仅作档案保留，**产品不加载、不打包**。保存非 Unicode 编码时的不可编码字符由 `encoding_rs` 按 WHATWG 标准以数字字符引用 `&#xNNNN;` 写出（见 F-02 §2.2）。

示例行：

```
丄	上
丅	下
乆	久
纟	糸
```

### 3.4 u2b2.tsv — BIG5 组字式回退表（已弃用，仅存档）

| 属性 | 值 |
|------|-----|
| 编码 | UTF-8 with BOM |
| 行尾 | CRLF |
| 行数 | 995 |
| 行格式 | `键<TAB>值`——键为 1 字，值为组字式（字符构造式）字符串 |

**语义**：F-02 保存为 BIG5 时异体字也无果后的"组字式"兜底。

示例行：

```
頮	[(水/廾)*頁]
鷉	[(虒-儿+几)*鳥]
氎	[(畾/(冗-几+互))*毛]
聦	[耳*(匆/心)]
```

**组字式语法**（由样本归纳；以 TextPro 原实现为准）：

| 运算符 | 含义 | 示例 |
|--------|------|------|
| `[]` | 整体界定 | `[(水/廾)*頁]` |
| `/` | 上下组合 | `水/廾` = 水上廾下 |
| `*` | 左右组合 | `耳*(匆/心)` |
| `-` | 笔画/部件去除 | `(虒-儿)` |
| `+` | 部件添加 | `(-儿+几)` |
| `~` | 包围/包含（样本出现于 `[(~(償…` 形式） | 待开发期与 TextPro 对照确认 |

### 3.5 加载器接口（Rust 端约定）

```rust
// core/data_tables.rs —— 纯文本加载，无二进制解析
pub struct VariantGroups { pub groups: Vec<Vec<String>> }   // fc1/fc2

pub fn load_variant_groups(path: &Path) -> Result<VariantGroups>; // 按行、按码点切分
```

## 五、产品影响与文档修正

本次逆向澄清了一个事实：**fc1/fc2 是"文件比较"功能的异体字组表，不是简繁转换词组表**（此前 PRD v0.3 §1.5 中"fc1/fc2 作为佛经/古文简繁补充表"的说法有误，已修正）。相应地：

1. **F-03 简繁互转**：不再叠加 fc1/fc2；转换链简化为 `括号对豁免 → OpenCC → 用户自定义表 → 歧义诊断`。
2. **F-06 文件比较**：完全等同/部分等同两档直接加载 `fc1.txt` / `fc2.txt`。
3. **F-02 编码保存**（v0.5 更新）：`u2b1.tsv` / `u2b2.tsv` 弃用，不打包、不加载；编码互转与不可编码字符处理改由 `encoding_rs`（WHATWG 标准）承担——数字字符引用 `&#xNNNN;` / 保存前预检弹窗 / 改存 UTF-8。
4. **架构**：`core::data_tables` 从"二进制 .dat 解析器"简化为"纯文本表加载器"；`src-tauri/data/legacy/` 中不再打包任何 `.dat`。
5. **s2t/t2s.dat 不打包**（OpenCC 取代，v0.3 已确认）。
