## 一、项目定位

### 1.1 产品名称

**AioTextEditor**（中文名：爱欧文本编辑器）

### 1.2 一句话定义

面向中文古籍整理、佛经校勘、内容编辑人群的**跨平台深度文本编辑器**，在保留轻量、便携特性的同时，提供专业级的简繁转换、多编码互转、正则替换、文件比较与批量处理能力。

### 1.3 目标用户

| 用户类型 | 典型场景 |
|---------|---------|
| 古籍 / 佛经电子化整理者 | 扫描或 OCR 后的文本需要 GBK / BIG5 / UTF-8 互转、繁简统一 |
| 内容编辑 / 校对人员 | 重复行去除、自动排版、规范段落 |
| 网站内容运营 | 批量清理论坛干扰码、统一空白与标点 |
| 程序员 / 高级用户 | 自定义替换表 + 中文正则表达式 + 批量脚本化处理 |
| 一般中文写作者 | 需要一个轻量、绿色的纯文本编辑器，不依赖 Office |

### 1.4 与已有方案的差异

- **vs TextPro 6.5**：保留几乎全部专业功能；脱离 Windows 限制；用现代 UI；文件以 JSON/YAML 配置，不再依赖注册表；支持 macOS / Linux。
- **vs iml-editor-lite**：从纯 Markdown 编辑器扩展到专业中文字处理；保留 iml 的轻量 Tauri 2 壳层、单一 API 接口模式、CodeMirror 内核。
- **vs VS Code / Sublime**：专注中文纯文本处理场景，开箱即用，无需安装扩展即可完成繁简转换、文件比较、批量转码。
- **vs NotePad++**：原生 Unicode、加词组级简繁判断、自定义替换表 + 中文字符集正则。
- **vs OpenCC CLI**：OpenCC 是底层引擎；AioTextEditor 在其之上加编辑器、UI、批处理、可视化歧义提示；OpenCC 的 17 种转换全部内置为"功能"菜单的可选项。

### 1.5 繁简转换引擎：OpenCC（基于 BYVoid/OpenCC）

- **词库来源**：OpenCC 1.4.2 标准词库（STCharacters、STPhrases、TSCharacters、TSPhrases、HKVariants、JPVariants、TwVariants、TwPhrasesIT、TwPhrasesName、TwPhrasesOther 等）。
- **17 种转换**：s2t、t2s、s2tw、tw2s、s2twp、tw2sp、s2hk、hk2s、t2tw、tw2t、t2hk、hk2t、t2jp、jp2t、t2seal、seal2t、s2seal。
- **集成方式**：使用 `opencc-sys` crate 静态链接 OpenCC C++ 库；OpenCC 的全部 JSON 词典在编译期嵌入到二进制。
- **优势**（vs TextPro 自带的 s2t/t2s.dat 词表）：
  - OpenCC 提供"标准异体字"识别，繁体转换后可避免使用不规范异体字。
  - 支持台湾、香港等地方化繁体的双向转换。
  - 支持"歧义片段"诊断（CLI `--ambiguities`），可直观提示一对多的转换结果。
  - 词库维护由社区持续更新，比 TextPro 内置词库更现代。
- **不抛弃 TextPro 特性**（数据已全部转换为开放文本格式，见[数据字典](./06-data-dictionary.md)）：
  - **异体字组表 `fc1`/`fc2`**：用于文件比较"忽略异体字（完全等同 / 部分等同）"，非简繁转换数据。
  - **不转换括号对**（`[]` 等）作为前处理保留。
- **已废弃的 TextPro 数据**（均不再随包分发）：
  - 简↔繁单字表 `s2t.dat`/`t2s.dat`：与 OpenCC 词库完全同质，按 v0.3 决策由 OpenCC 取代。
  - BIG5 回退表 `u2b1.dat`/`u2b2.dat`：按 v0.5 决策弃用，改用 GitHub 上的 [`encoding_rs`](https://github.com/encoding-rs/encoding_rs)（WHATWG Encoding Standard 参考实现）承担全部编码互转——原生支持 **UTF-8、UTF-16、GBK、GB2312、GB18030、Big5、ISO-8859-1** 等编码；不可编码字符按标准以数字字符引用 `&#xNNNN;` 写出。
- **用户自定义替换表**通过 OpenCC 原生"内联字典（Inline Dictionary）"机制实现：程序把用户的 `A/B=目标` 自动转换为 OpenCC `{"type":"inline","entries":{...}}` JSON，作为转换链的最后一步叠加。
- **逆转换提醒**：对于"一对多"的转换字符，提供"OpenCC 歧义片段"诊断（CLI `--ambiguities` 风格）。

### 1.6 设计哲学（仿 iml 风格的三条规矩）

1. **没有欢迎页，启动即编辑** —— 上次未保存的内容自动恢复，但不强制建索引、不弹窗邀请。
2. **存不存由用户决定，自动保存默认关闭** —— 一切写盘操作需要用户明确触发。
3. **不在背后做事** —— 没有云同步、没有 AI 写作、没有遥测，也**没有任何网络请求**：应用不检查更新、不自动更新版本，完全离线运行。

## 三、范围控制

### 3.1 必须实现（MVP v1.0）

下列功能必须在 1.0 版本完整交付：

1. 多标签编辑、文件新建 / 打开 / 保存 / 另存为
2. UTF-8 / UTF-16 / GBK / GB2312 / GB18030 / BIG5 / ISO-8859-1 自动识别与读写互转（`encoding_rs`）
3. **简繁互转（基于 OpenCC 1.4.2；提供 s2t、t2s、s2tw、tw2sp、s2hk 等 10+ 种常用转换；用户词典叠加）**
4. **自定义替换表（= 分隔）；自动适配为 OpenCC 内联字典与转换链叠加；保留 TextPro 风格的多对一 `A/B=目标` 写法**
5. 中文增强正则（与 OpenCC 转换不冲突，可与替换表串联执行）
6. 文件比较（双窗平铺，差异状态栏提示）
7. 文件合并（手工 + 正则自动）
8. 批处理（输入输出编码可选、递归子目录、备份、改写判断；批处理步骤中"OpenCC 转换"为可用步骤）
9. 删除段内回车、规范行首、删除行末空格、删除空行
10. 半角 ↔ 全角转换、半角字符删除
11. 按行排序、删除重复行
12. 字数统计、段落计数、转到某行
13. 自定义快捷键
14. 设置项（采用 JSON 持久化、跨平台用户目录）
15. **OpenCC 歧义片段诊断**（参考 CLI `--ambiguities`，在转换结果上显示一对多区段，方便校对）

### 3.2 后续版本（v1.1+）

- 自定义工具栏（带图标）
- 自动分段、控制行宽、简单排版
- 匹配括号 / 嵌套转换
- 半角引号转全角引号
- 段落空一行
- 竖排符号横转
- 打印 / 打印预览
- 文件关联、macOS / Linux 右键菜单
- TTS 朗读
- 30 条光标位置记忆

### 3.3 不在范围

- 完整的 Markdown / 富文本渲染（这是 iml-editor-lite 的事，与本产品定位不同）
- AI 写作助手、云同步
- 内置浏览器 / 终端
- 移动端（iOS / Android）

## 四、产品差异化亮点

1. **完全保留 TextPro 专业流程**：长期用户无需重新学习。
2. **跨平台原生体验**：使用系统 WebView，安装包控制在 12 MB 以内（参考 iml Lite 的 < 4 MB 目标，但要打包 OpenCC C++ 静态库约 +1 MB）。
3. **OpenCC 引擎 + TextPro 兼容**：业内最权威的中文简繁转换词库，覆盖台湾 / 香港地方化习惯；同时保留 TextPro 的异体字比较表（开放文本格式）。
4. **自定义替换表可叠加 OpenCC**：用户用熟悉的 `A/B=目标` 格式编表，无需学习 OpenCC 的 JSON 配置语法。
5. **内置中文增强正则**：GBK / BIG5 / 中文数字 / 天干地支等字符集，无需扩展。
6. **批处理可在 UI 上完全配置**：无需命令行。
7. **歧义片段可视化**：参考 OpenCC CLI 的 `--ambiguities`，转换后直接标注一对多区段。

## 五、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| OpenCC 三平台 cmake 构建 | 跨平台打包失败风险 | 第 1 周就在 CI 上 3 平台验证 `opencc-sys`；选用 docs.rs 收录的版本 |
| OpenCC C++ ABI 与系统库冲突 | 链接错误 | 使用 `link-cplusplus` crate，确保 CMake target `opencc` 独立 |
| OpenCC C API 仅接受磁盘路径 | 词典必须落盘 | 运行时把 JSON 配置写 `%TEMP%/aotext-cc-*.json`，OpenccHandle 持有句柄直到 Drop |
| 简繁转换一词多义问题 | 转换结果可能有少量错字 | 文档警示 + OpenCC 歧义片段诊断弹窗 + 用户词典可编辑 |
| BIG5 编码在 macOS / Linux 上没有内置字体 | 显示异常 | 打包字体内置或提示用户安装 |
| 非 Unicode 编码存在不可表示字符 | 直接保存 BIG5/GBK 会丢字 | `encoding_rs` 按 WHATWG 标准生成数字字符引用 `&#xNNNN;` + 保存前预检弹窗（改存 UTF-8 / 以引用继续 / 取消） |
| 自动编码识别误判 | 打开文件乱码 | 提供"重新载入"功能手选编码 |
| WebView 差异 | 部分平台功能不可用 | 走 iml 已验证的 macPDF / 平台适配方案 |
| 安装包体积超目标 | 用户体验下降 | CI 跑 `packaging.test.ts` 阈值测试 |

## 六、验收标准（v1.0）

- 安装包大小：Windows < 16 MB，macOS < 12 MB，Linux AppImage < 18 MB（包含 OpenCC 静态库后上调）。
- 启动时间：冷启动 < 1.5 s（8 GB 内存 SSD）。
- 打开 100 万字纯文本文件应不卡顿（按需启用 CodeMirror 虚拟滚动）。
- 全部 16 个 MVP 功能 ≥ 90% 测试覆盖率（Rust 端命令）。
- OpenCC 17 种转换方向均跑通且结果与 OpenCC CLI 一致。
