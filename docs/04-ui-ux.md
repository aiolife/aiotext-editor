# AioTextEditor UI / UX 设计要点

**版本**：v0.1

> 本文档聚焦在"对照 TextPro 的菜单/工具栏布局，移植到 Tauri + 现代 WebView 的写法"。

**菜单栏形态**（PRD v0.5 §3.5）：只有「文件 编辑 功能 视图 帮助」五个纯文字入口，没有按钮、没有 `▾`、不重复显示应用名（窗口标题已有）。菜单栏与状态栏均可在设置中显示或隐藏；隐藏菜单栏后可用 `Ctrl + ,` 打开「选项」恢复。图标化的自定义工具栏属 v1.1（见 §2.3）。

### 2.3 视图

（顺序即菜单里的实际顺序）

- 菜单栏 ☑（即设置里的 `showToolbar`；勾掉会收起整条顶栏，用 `Ctrl + ,` 可恢复）
- 状态栏 ☑
- 行号 ☑
- 自动换行 ☑（即设置里的 `editor.wrap`，命令 `view.toggleWrap`，可在「自定义快捷键」里给它绑键）
-（分隔）**字数统计** / **统计选定文字出现的次数** / **显示段落数**（v0.6）

不可见字符三开关（**显示空格字符** / **显示行尾字符** / **显示换段符**）放在
**选项 → 编辑器**里，**默认全部勾选**：空格画 `·`、制表符画 `→`、行尾画 `¬`、
段落最后一行画 `¶`（与行尾符同一位置时优先画 `¶`）。
画出来的是 **CodeMirror 的 decoration**，不是文档内容——编辑、复制、保存、字数统计照常按真实字符走。

字数统计给出**多维度**（口径写在 `src/shared/textStats.ts`，有单测锁定）：

| 维度 | 口径 |
|------|------|
| 中文字数（汉字） | CJK 主区 + 扩展区 + 兼容表意文字，`々` `〇` 也算 |
| 中文标点 | `、` `。` `「」` `【】` `……` `——` 及全角形标点（不含全角空格 `U+3000`） |
| 字母个数 | 所有 Unicode 字母（拉丁 / 假名 / 谚文…），汉字不计入 |
| 单词个数 | 连续的字母/数字为一词（可含 `'` `-`）；**汉字不算词** |
| 英文标点 | ASCII 标点 |
| 数字个数 / 数字组 | 十进制数字符个数 / 连续数字算一组的组数 |
| 字符数 | 三种口径：不计空格与控制符、含空格、含空格与控制符；**代理对一律算 1 个字符**（`Array.from` 而非 `.length`，`𩅯` 不会数成 2） |
| 段落数 / 非空行数 | **两个不同口径**：段落 = 空行分隔的连续非空行块；非空行数 = trim 后非空的行数（也是「段间空一行」工具认的段落口径） |
| 字节数（UTF-8） | `TextEncoder` 实测 |
| 选定文字出现次数 | 全文范围内不重叠计数，含选区自身那一处 |

- 主题：跟随系统 / 浅 / 深
- 恢复默认设置（菜单末项）

### 2.4a 「文件」「编辑」里的二级菜单（v0.5）

菜单项后缀 `▸` 表示二级菜单（鼠标划过即展开；主项与子面板同属一个容器，横移过去不会误收起）：

- **文件 → 重新载入 ▸**：第一项「自动探测…」是原来的编码选择对话框；其后 7 项按指定编码**硬重读**当前文件（GBK / GB18030 / BIG5 / UTF-8 / UTF-16LE / UTF-16BE / NFO 437）。
- **文件 → 编码转换 ▸**：内容一个字符都不改，只按目标编码重写文件——所以 GBK ⇄ BIG5 也能互转；目标编码表示不了的字符走与保存同一套「询问 / 数字字符引用 / 改存 UTF-8」流程。
- **编辑 → 自定义替换 ▸**：直接列出「替换表管理」里的表名（带条数提示），点一下就对正文跑那张表；一张表都没有时子面板里显示「（暂无）」。

`NFO (437)`（CP437）是 `encoding_rs` 不支持的编码（WHATWG 表里没有），由 `core/encoding.rs` 自带的 256 项表处理；它只用于「重新载入 / 打开时指定编码」，不参与自动探测。

> **落地形态（第七阶段）**：F-08 批处理收进工具栏的「批处理…」对话框。上半是配置：① 路径输入框（可直接键入 / 粘贴，或用「浏览…」选原生目录）→「添加」入列，可多目录，旁边是「递归子目录」开关；输入就绪后**自动预览**「将处理 N 个文件（深度=1/∞）」（防抖 350ms），避免误把空目录或全无效路径送进批处理。② **双栏步骤选择**（沿用 TextPro 习惯）：左栏「工具库」按 4 组铺开 F-09 的 17 个会改写正文的工具（`inspectsOnly` 的「匹配括号」被过滤掉——它在批处理里是无操作），点一下即加入右栏「流水线」；右栏按序显示并可 ↑ 上移 / ↓ 下移 / × 移除。③ 运行设置：输入 / 输出编码（默认自动探测 / 跟随输入；选不同编码即为编码互转）、「备份（.bak）」、「保留 mtime」。启动后切到运行态：进度条 + `已完成/总数（已改 N，错误 M）· 正在处理 <文件>`，错误面板按阶段（enumerate / read / process / backup / write / mtime）染色并列出路径与原因，可「取消」（当前文件跑完即停）；结束时给出汇总「处理 N 个文件 · 改写 N · 未变 N · 备份 N · 错误 N · 耗时 Nms」。**进度由后端合并上报**（见架构 §10.6），长任务约 2Hz，短任务只有终态。

> **落地形态（第六阶段）**：① 比较入口「比较…」按钮（仅在 ≥ 2 个标签时可用；比较进行中禁用）：选择对照标签 + 4 个忽略项（回车 / 半角空格 / 全角标点 / 半角标点）+ 异体字策略（不忽略 / 完全等同 / 部分等同）+ 平铺方向（上下 / 左右）。开始后双栏平铺 A / B 窗（A 可编辑、B 只读不抢焦点，标题标"只读"），CompareBar 显示差异计数与双方字符，`F5` 跳下一处不一致（最后一处给出提示）、`Shift+F5` 从两个光标处重新比较（重选同步起点）；② 合并入口「合并…」按钮：手工合并页签（多选源文件 + 可选排序关键字 + 输出文件另存为）/ 自动合并（正则）页签（选源目录 + 源文件名正则 + 输出模板 + 排序关键字，输出落在源目录），可选覆盖已存在的输出文件，结果以"写出 N 个合并文件…"通知 + 跳过项明细呈现。表内列出的 `Ctrl + Alt + F/H` 等**整理工具快捷键尚未接线**，待 F-11 §11.2 落地。

> **落地形态（第五阶段）**：以上 18 项收进工具栏的「整理 ▾」菜单，**按后端目录分 4 组**——行处理 / 空格与全半角 / 标点与括号 / 排版与分段；菜单顶部另有「常用」快捷区（简单排版、删除空行、删除行末空格、段间空一行）可直接点用。有可调选项的工具（共 11 个，菜单里带「…」）点开**选项对话框**：上方选项表单，下方依次是「整篇 / 选中文本」作用范围与实时预览（防抖 250ms，含该步骤的统计说明与结果文本）；纯检查型的「匹配括号」标「仅检查」，只出提示条不改正文。表内列出的 `Ctrl + Alt + F/H` 等**快捷键尚未接线**，待 F-11 §11.2 的快捷键配置落地。

### 3.5 设置（选项）

```
┌──────────────────────────────────────────────────────────────┐
│ [外观] [编辑器] [转换] [比较] [快捷键]                        │
├──────────────────────────────────────────────────────────────┤

└──────────────────────────────────────────────────────────────┘
```

- **改动即存**（防抖 300ms）+ 立即生效，对话框没有「确定 / 取消」；关闭仅收起。
- 五个页签：外观 / 编辑器 / 转换 / 比较 / 快捷键。「选项…」默认落外观页；「自定义快捷键…」直达快捷键页。
- 「快捷键」页每行 = 命令名 + 当前键位 + 录制 / 清除 / 默认三个动作。**录制**态显示「按下组合键…」（按 Esc 取消）；冲突行标红并在页内汇总，与系统冲突的组合拒绝分配并说明原因。
- 「清除」＝显式解绑（该键位不再触发任何命令），与「还没配过」区分；「默认」把单行恢复成注册表默认键位。
- **「显示菜单栏」是唯一会收起顶栏的开关**：关掉后菜单栏整条消失（设置入口也随之不见），恢复靠 `Ctrl + ,` 打开「选项」——这条兜底路径必须始终可用，不得再改。

## 四、交互细节

### 4.1 标签

- **未保存**：圆点（●）在标题左侧。
- **关闭**：双击标签 = 关闭；双击空白处 = 新建；右键菜单 = 关闭 / 关闭其他标签 / 全部关闭 / 保存 / 另存为…。
- **拖动**：标签可拖出为独立窗口（v1.2）。

### 4.2 状态栏

按段从左到右：
1. 文件路径（悬停显示完整路径；尚未保存时显示「未保存」）。
2. 编码（点击 → 切换编码并重新加载）。
3. 行尾（LF / CRLF / CR，点击切换）。
4. BOM（有 / 无）。
5. 行 / 列。
6. **右对齐的三项计数：`汉字 42 · 单词 3 · 128 字节`**（v0.7 起；此前是「N 字符（M 码元）」）。
7. 未保存标记 `● 未保存`（只有 dirty 时出现）。

> 状态栏这三项与「视图 → 字数统计」**同一个 `countTextStats`**，口径完全一致；
> 状态栏只放扫一眼就要的数，完整的 13 项在字数统计对话框里。
>
> 为了不跟输入抢 CPU：≤20 万字符**就地算**（几毫秒），更大的文档走 React 的延迟值 ——
> 数字滞后一帧，换打字不卡（见 `StatusBar` 的 `INSTANT_LIMIT`）。
> 这也意味着 1 MB 以上的文档，最后敲下的那个字可能要等一拍才会反映到这三个数字上。

### 4.3 拖放

- 全窗口接收 drop。
- 文件路径：根据平台 → `app_state.pending_open`。

### 4.4 暗色主题

- 默认跟随系统（`color-scheme: light dark`），可在「设置 → 外观 → 主题」切换为固定浅色 / 深色。
- **实现**：切主题即切 `color-scheme` 并同步 `data-theme` 属性；配色建立在 CSS 系统色（`Canvas` / `CanvasText` / `ButtonFace` …）之上，**无需维护第二套颜色变量**。
- 字体族与字号通过 CSS 变量（`--editor-font-family` / `--editor-font-size`）下发到 `.cm-content`，比较模式多窗格共用。
- 自定义替换表、批处理等需要保留品牌色（绿色 `var(--brand)`）。

### 4.5 提示与反馈（Toast）

- 所有操作反馈走**右下角堆叠的 Toast**，可多条同时存在，**不再互相顶掉**。
- 四个级别：`success`（绿）/ `info`（蓝）/ `warn`（橙，如快捷键冲突）/ `error`（红）。
- 自动消失：普通提示 4s、**错误 8s**（留出阅读时间）；每条都可手动关闭（右侧 ×）。
- 同屏最多 4 条，超出丢**最旧**的一条——刷屏时用户最该看的是「刚刚发生了什么」。
- 层级高于对话框遮罩，所以对话框里触发的提示也看得见。
- 无障碍：`error` 用 `role="alert"`（读屏立刻播报），其余用 `role="status"`。

## 八、流程示意

### 8.1 "简繁转换" 流程（基于 OpenCC）

```
[用户选文本 / 全文] → [功能 → 简→繁 / 繁→简 / 其他 OpenCC 方向]
   → 弹出"简繁转换"子对话框（方向、范围、括号对豁免、用户表、歧义诊断）
   → [预览 Diff]（可选）→ 显示前 200 行差异预览
   → [转换]
        Rust 端：OpenCC 转换链执行
        （括号对豁免 → OpenCC 字典 → 用户内联字典）
   → 完成后自动弹"歧义片段"弹窗（最多前 100 处，一行一候选）
        点击行 → 跳转文中位置人工校对
   → 状态栏 Snackbar：转换 X 字，Y 处歧义
```

### 8.2 "保存为非 Unicode 编码（BIG5 / GBK 等）" 流程

```
[用户 Ctrl+S] → 检测到目标编码为非 Unicode（BIG5 / GBK / GB2312 等）
   → invoke('fs_check_mappable', { text, encoding })     // 保存前预检
   → 有不可编码字符（N 处）→ 前端弹 Modal：
       [文件 [name] 有 N 个字在 [编码] 中不存在。]
       [改存为 UTF-8（推荐）] [以 &#xNNNN; 引用继续] [取消]
   → 用户选择后 → invoke('fs_write', { opts: { encoding, unmappable: ... } })
   → Rust：encoding_rs 编码写出（WHATWG 标准行为）
   → 状态栏 Snackbar：已保存为 [编码]；M 处字符以数字字符引用写出
```

（v0.5：TextPro u2b1/u2b2 异体字/组字式回退已弃用，不再出现于流程与选项。）

## 九、设计原则

1. **不藏功能**：所有功能在一级菜单或工具栏 1 次点击可达。
2. **不破坏习惯**：TextPro 老用户可以零成本迁移。
3. **不漂亮但清晰**：美观让位功能，纯文本编辑场景。
4. **不沉默也不唠叨**：错误用 Modal、提示用 Snackbar、状态用状态栏。
